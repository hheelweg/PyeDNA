## 01 — Build a DNA–dye system

PyeDNA constructs an ideal double-stranded DNA structure from a nucleotide sequence, replaces selected nucleotides with prepared dye-linker residues, and generates the corresponding AMBER topology and coordinate files for molecular dynamics.

The system is defined by two inputs:

1. a `struc.params` file located in the current working directory;
2. a prepared dye library referenced by the `DYE_DIR` environment variable.

The DNA structure itself is generated internally from a NAB template distributed with PyeDNA, so no DNA PDB file is required from the user.

### Requirements

The structure-building workflow requires:

- PyeDNA
- AmberClassic (NAB)
- AmberTools (`tleap`, `pdb4amber`)
- MDAnalysis
- a prepared dye library

The commands `nab`, `tleap`, and `pdb4amber` must be available in your environment.

### Working directory

Run the structure builder from a dedicated working directory containing a single configuration file:

```text
build_system/
└── struc.params
```

`create_structure.py` reads `struc.params` from the current working directory and writes all generated files there.

A typical setup is

```bash
mkdir build_system
cd build_system

cp "$PYEDNA_HOME/examples/struc.params" .
```

### Structure definition (`struc.params`)

An example `struc.params` is

```python
dna_sequence   = 'TGCACTCTCGAATGACCGAGCT'
dna_type       = 'double_helix'
dna_name       = 'dna'

dyes           = ['CY3', 'CY3', 'CY5']
dye_positions  = [13, 14, 11]
structure_name = 'dna_1nt'
```

#### `dna_sequence`

The DNA sequence of the first strand written from 5′→3′.

PyeDNA inserts this sequence into the selected NAB template, which automatically constructs the complementary strand and generates the initial DNA structure. The sequence therefore contains **only one strand**.

The sequence determines the length of the duplex and consequently the valid residue IDs that may later be selected in `dye_positions`.

---

#### `dna_type`

Selects the DNA template used for structure generation.

```python
dna_type = "double_helix"
```

PyeDNA currently loads

```text
$PYEDNA_HOME/data/dna_templates/double_helix.nab
```

which generates an ideal B-DNA duplex using NAB. Additional DNA templates may be added in the future by placing new `.nab` files into the `dna_templates` directory.

---

#### `dna_name`

Filename prefix of the intermediate DNA-only structure.

For

```python
dna_name = "dna"
```

PyeDNA generates

```text
dna.pdb
```

which contains the DNA before any dyes have been attached. This structure is useful for verifying residue numbering when selecting dye attachment sites.

---

#### `dyes`

Ordered list of dyes to attach.

```python
dyes = ["CY3", "CY3", "CY5"]
```

Each entry corresponds to one dye attachment and is matched directly to a directory inside the dye library.

For example,

```python
dyes = ["CY3", "CY5"]
```

requires two dye directories

```text
$DYE_DIR/
├── CY3/
└── CY5/
```

The same dye may appear multiple times if several copies are attached to the DNA.

The dye names should exactly match the directory names and filenames in the dye library.

---

#### `dye_positions`

Ordered list of DNA residue IDs to be replaced by the dyes.

```python
dye_positions = [13, 14, 11]
```

The two lists are matched element-wise:

```text
CY3 → residue 13
CY3 → residue 14
CY5 → residue 11
```

Consequently,

```python
len(dyes) == len(dye_positions)
```

must always hold.

The residue IDs refer to the DNA generated by NAB (`dna.pdb`), **not** Python indices.

A practical workflow is

1. choose the DNA sequence,
2. generate `dna.pdb`,
3. inspect the residue numbering in VMD,
4. select the desired attachment residues,
5. update `dye_positions`.

Avoid terminal residues, since the current attachment procedure requires neighboring nucleotides.

---

#### `structure_name`

Filename prefix of the final DNA–dye system.

For

```python
structure_name = "dna_1nt"
```

PyeDNA generates

```text
dna_1nt.pdb
dna_1nt_tleap.in
dna_1nt.prmtop
dna_1nt.rst7
```

---

## Dye library (`DYE_DIR`)

The environment variable

```bash
export DYE_DIR="/path/to/dye_library"
```

must point to the root of a prepared dye library, containing (ideally) geometry-optimized dyes.
For every unique dye listed in

```python
dyes = [...]
```
PyeDNA searches recursively below `DYE_DIR` for a directory with the same name.

For example,
```python
dyes = ["CY3", "CY3", "CY5"]
```

requires

```text
$DYE_DIR/
├── CY3/
│   ├── CY3.pdb
│   ├── attach_CY3.info
│   ├── CY3_del.mol2
│   ├── CY3_del.frcmod
│   └── connectparms.frcmod
└── CY5/
    ├── CY5.pdb
    ├── attach_CY5.info
    ├── CY5_del.mol2
    ├── CY5_del.frcmod
    └── connectparms.frcmod
```

Each dye directory must contain the following files.

### `<DYE>.pdb`

Three-dimensional structure of the dye including its phosphate linker groups.
PyeDNA uses this file to determine the attachment geometry and to position the dye on the DNA backbone.
🚧: *The construction of most of these files can also be handled internally via the ``create_dye.sh`` command.*

---

### `attach_<DYE>.info`

Defines the two phosphate linker groups.
The file specifies which linker atoms

- define the attachment geometry,
- are retained after attachment,
- are deleted during attachment,
- are renamed to DNA backbone atoms.

Every atom listed in this file must exist in `<DYE>.pdb`.

---

### `<DYE>_del.mol2`

AMBER residue template of the attached dye.

This file provides

- atom names,
- GAFF atom types,
- partial charges,
- residue connectivity.

The `_del` suffix indicates that atoms removed during attachment have already been deleted from the residue template.

---

### `<DYE>_del.frcmod`

Additional AMBER force-field parameters required for the dye.
Typical entries include missing bond, angle, dihedral and nonbonded parameters not contained in the standard GAFF force field.

---

### `connectparms.frcmod`

Additional force-field parameters describing the interface between the dye and the DNA backbone.
These parameters complete the bonded interactions between the GAFF-parameterized dye and the OL15 DNA force field.

### Running the structure builder

From the working directory containing `struc.params`, execute
```bash
bash create_structure.sh
```
The principal output files are

```text
dna.pdb              # DNA-only structure
dna_1nt.pdb          # DNA–dye structure
dna_1nt_tleap.in     # generated tleap input
dna_1nt.prmtop       # AMBER topology
dna_1nt.rst7         # AMBER coordinates
```

These files form the starting point for the molecular dynamics workflow.
